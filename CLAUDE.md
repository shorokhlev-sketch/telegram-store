# Apple Store TG: бот, канал, Mini App и сайт для магазина техники

Спека v2 от 28.09.2026. Предыдущая версия (только iPhone, только Mini App) осталась в приватной истории. Публичная версия: личные данные заказчика, адреса серверов и коммерческие условия убраны.

## Цель
Замена Avito для одного магазина б/у техники. Продавец заводит лот через бота: телефон, ноутбук, часы, что угодно. Теги ставятся автоматически по полям: устройство, производитель, модель, состояние, комплект, батарея, цена. Готовый лот публикуется одновременно в трёх местах:
1. в Telegram-канал обычным постом (посты идут подряд);
2. в Mini App;
3. на сайт (тот же фронт, открытый в браузере).

На сайте и в Mini App покупатель фильтрует лоты по тегам. Связь с продавцом:
- из канала: кнопка «Написать продавцу» открывает личку продавца с уже вписанным текстом про лот;
- из Mini App и с сайта: покупатель жмёт «Купить», бот сам пишет продавцу заявку с контактами покупателя.

После продажи лот автоматически исчезает везде: пост из канала удаляется, карточка пропадает с витрины.

## Правила работы для Claude
- Никаких поясняющих плашек и слоганов в UI (Лев 28.09): если кнопка или заголовок уже это говорят - не повторять серым текстом. Разрешены подписи, заголовки, данные, ошибки при сбое, одна строка успеха после действия.
- Никаких эмодзи ни в текстах бота, ни на сайте, ни в постах (Лев 28.09). Тест `test_no_emoji_in_user_facing_bot_texts` это стережёт.
- Работа идёт лупом по `LOOP.md`: там блок ПРАВИЛА, состояние этапов и условия остановки. Этапы - из раздела «Порядок сборки».
- Не добавляй функции из раздела «Вне MVP». Если видишь реальную необходимость - запиши в `LOOP.md` → «Вопросы к Льву» и не делай.
- Каждый сервисный модуль покрывай pytest-тестами (tags, publisher с моком Bot API, sales, leads, валидация initData, media).
- Секреты только через `.env`. `.env.example` держи в актуальном состоянии.
- Код, идентификаторы и комментарии на английском. Тексты для пользователя на русском.

## Стек
- Python 3.12, FastAPI, aiogram 3 (webhook внутри FastAPI, один процесс)
- SQLAlchemy 2 (async) + aiosqlite, Alembic для миграций, SQLite в режиме WAL
- Pillow для ресайза фото
- Frontend: React 18 + Vite + TypeScript + Tailwind. Одно приложение на два режима: внутри Telegram (есть `window.Telegram.WebApp.initData`) - Mini App, в обычном браузере - сайт.
- Lab: systemd + nginx на staging-сервере под подпутём (`deploy/lab-deploy.sh`, хост и адрес из `DEPLOY_HOST` и `LAB_URL`), FastAPI сам отдаёт `web/dist`.
- Прод: docker compose (app, caddy) - этап 10.

## Схема БД
```sql
items(
  id INTEGER PK,
  public_id TEXT UNIQUE,          -- короткий id, 8 символов base32
  status TEXT,                    -- draft | active | sold
  category TEXT,                  -- iphone | ipad | macbook | watch | airpods | other
  device_type TEXT,               -- phone | tablet | laptop | watch | headphones | other
  brand TEXT,                     -- "Apple" для каталога, ручной ввод для other
  model TEXT,                     -- "iPhone 15 Pro" / "MacBook Air 13 M2" / ручной ввод
  generation TEXT,                -- из каталога Apple, для other NULL
  year INTEGER,                   -- год выпуска, ручной ввод для other; для Apple NULL
  storage_gb INTEGER,             -- NULL, если у устройства нет выбора памяти
  variant TEXT,                   -- прочая опция каталога: "45 мм", "16 ГБ RAM"; NULL если нет
  color TEXT,
  battery_health INTEGER,         -- 0..100, NULL = не указано (можно пропустить)
  grade TEXT,                     -- A | B | C
  kit_json TEXT,                  -- ["box","cable","adapter","receipt"]
  price INTEGER,                  -- рубли, целое
  note TEXT,
  created_by INTEGER,
  created_at, published_at, sold_at
)
photos(id PK, item_id FK, kind, tg_file_id, file_unique_id, position,
       duration, file_size, cached_preview, cached_full)       -- таблица медиа: kind = photo | video
channel_messages(id PK, item_id FK, chat_id, message_id, kind) -- kind: media (cta - legacy до 24.09)
tags(id PK, slug UNIQUE, label, kind)   -- device|brand|model|storage|color|grade|battery_band|price_band|kit
item_tags(item_id FK, tag_id FK, PK(item_id, tag_id))
leads(id PK, item_id FK, source, buyer_name, buyer_contact, buyer_tg_id, buyer_username,
      created_at, notified_at)                                 -- source: app | site
events(id PK, item_id FK, type, payload_json, created_at)      -- created|published|sold|delete_failed|lead|notified
subscribers(tg_id BIGINT PK, username, first_name, subscribed BOOL DEFAULT 1,
            created_at, updated_at, blocked_at)                -- покупатели бота; blocked_at = бот заблокирован
```
Индексы: `items(status, published_at)`, `item_tags(tag_id)`, `leads(item_id)`.
Существующие лоты при миграции получают `category=iphone`, `device_type=phone`, `brand=Apple`, у фото - `kind=photo`.

## Ассортимент
- **Apple с меню** (`catalog.py`): iPhone, iPad, MacBook, Apple Watch, AirPods. Цепочка: категория → модель → опции, заданные у категории (память / размер корпуса / RAM) → цвет. У AirPods нет памяти, у Watch вместо памяти размер корпуса (`variant`). Каталог покрывает актуальные модели за последние ~6 лет, чтобы кнопок было обозримо.
- **Всё остальное** (не-Apple и редкий Apple вроде iMac): тип устройства кнопками (Телефон / Планшет / Ноутбук / Часы / Наушники / Другое), затем текстом производитель, модель, год выпуска (4 цифры, 2000..текущий), память - кнопками с вариантом «Пропустить».
- Тип устройства - закрытый список, а не свободный ввод: иначе фильтр «какое устройство» развалится на «ноут», «ноутбук», «Laptop».
- Производитель при ручном вводе нормализуется для тега: регистр, пробелы, частые синонимы (`samsung`, `Samsung Electronics` → `Samsung`).

## Теги
- Свободного ввода тегов нет. `build_tags(item)` детерминированно строит слаги из полей.
- Слаги: `device:phone`, `brand:apple`, `model:iphone-15-pro`, `storage:256`, `color:black-titanium`, `grade:a`, `kit:box`, `battery:100|90plus|85plus|below85`, `price:0-30k|30-60k|60-100k|100k-plus`.
- Лот без батареи не получает тег `battery:*`. Лот без памяти не получает тег `storage:*`.
- Теги пересчитываются при публикации и при изменении лота.
- Фильтр в API: `?tags=a,b,c`. Между разными kind - AND, внутри одного kind - OR.

## Бот: визард создания лота
- Доступ только для `ADMIN_IDS`. Остальным бот отвечает ссылкой на Mini App - с этапа 11 вместо ссылки клиентский режим, см. «Бот: клавиатуры и покупатели».
- `/new` запускает FSM. Шаги:
  1. медиа: фото и короткие видео, от 1 до 10 штук, хотя бы одно фото, кнопка «Готово»;
  2. «матрёшка» (Лев 29.09): производитель (Apple, Samsung, Xiaomi, Huawei, Honor, Google, OnePlus, Nothing, Sony, Lenovo, «Другой» → текстом через `normalize_brand`) → устройство (Apple: iPhone / iPad / Mac / Watch / AirPods / Другое; остальные: Телефон / Планшет / Ноутбук / Часы / Наушники / Другое) → серия (только Apple и только если моделей в категории больше 8: iPhone по поколениям, iPad / Mac / Watch по семействам; серия из одной модели сразу выбирает модель) → модель. На каждом вложенном уровне «← Назад» на уровень выше. Серия хранится только в FSM: после рестарта визард спрашивает её заново;
  3. ветка Apple: модель → опции категории → цвет. Apple «Другое»: тип устройства → модель → год → память (можно пропустить) → цвет (текстом, можно пропустить). Другие производители: модель → год → память → цвет (тип устройства уже выбран на шаге «устройство»);
  4. battery health: число 0..100, для AirPods и «Другое» можно пропустить;
  5. комплект: мультивыбор с галочками;
  6. состояние: A/B/C с пояснением;
  7. цена: целое число;
  8. заметка: можно пропустить.
- Видео: Bot API скачивает файлы только до 20 МБ. Видео больше 20 МБ или длиннее 60 с бот не принимает и объясняет почему. Видео, отправленное файлом (document с video/*), тоже принимается, если укладывается в лимит.
- После каждого шага данные пишутся в черновик `items.status=draft`. Рестарт сервера не теряет ввод, `/new` предлагает продолжить черновик.
- Финал: предпросмотр 1:1 как пост в канале (фото, подпись, кнопки) и кнопки «Опубликовать», «Изменить поле», «Удалить черновик». «Изменить поле» знает о ветках: «Производитель» начинает матрёшку заново и сбрасывает зависимые поля, «Модель» у Apple - с устройства, у остальных - только текст модели.

## Публикация (publisher.py)
- Пост в канал - одно сообщение `send_photo`: первое фото лота, подпись из `post_render` (лимит 1024 символа) и две inline-кнопки:
  1. «Написать продавцу» - `https://t.me/{SELLER_USERNAME}?text={urlencoded}`, текст: `Здравствуйте, интересует {title}, лот {public_id}`;
  2. «Открыть в приложении» - `https://t.me/{BOT_USERNAME}/{MINIAPP_SHORT_NAME}?startapp=item_{public_id}`.
- Альбом не используется: медиагруппа не поддерживает inline-кнопки, а отдельное сообщение с кнопкой отклонено (24.09). Остальные фото и видео видны в Mini App и на сайте.
- Если `SELLER_USERNAME` пуст, кнопки «Написать продавцу» нет.
- `message_id` поста сохраняется в `channel_messages` в той же транзакции, что и перевод в `active`.
- Глобальный asyncio.Lock и пауза между отправками. На `RetryAfter` ждать и повторять.

## Бот: клавиатуры и покупатели
Этап 11: у бота всегда есть кнопки внизу, и бот работает не только для продавца, но и для покупателей.

**Факт Telegram, на котором всё построено.** Mini App, открытый с reply-кнопки (`KeyboardButton(web_app=...)`), получает пустой `initData`: без личности пользователя, только `Telegram.WebApp.sendData(...)`, который приходит боту сообщением `web_app_data` от этого пользователя и закрывает приложение. Из меню-кнопки чата, inline-кнопок `web_app` и прямых ссылок t.me initData есть. Поэтому:
- адрес приложения для кнопок бота - `PUBLIC_BASE_URL` со слэшем на конце (`https://staging.example.com/shop/`), карточка лота - `{PUBLIC_BASE_URL}/item/{public_id}`;
- админка в Mini App открывается из меню-кнопки «Магазин» слева от поля ввода (там initData есть).

**Меню и команды на старте** (вместе с `set_webhook`, только при `SET_WEBHOOK_ON_START=1`): меню-кнопка чата `MenuButtonWebApp` «Магазин» → адрес приложения, для всех. Команды: по умолчанию `/start`; для каждого из `ADMIN_IDS` (`BotCommandScopeChat`) - `/new`, `/list`, `/sold`, `/backup`, `/cancel`, `/start`. Ошибки логируются, старт не падает.

**Постоянные reply-клавиатуры** (`is_persistent`, `resize_keyboard`), одна строка:
- админ: «Магазин» (web_app → приложение) + «Новый лот»;
- покупатель: «Магазин» + «Отключить уведомления» или «Включить уведомления» по текущему состоянию.
Клавиатура приходит с `/start` и после действий, которые её меняют: переключение уведомлений, подтверждение публикации у админа. `ReplyKeyboardRemove` в боте не используется, inline-сообщения визарда клавиатуру не снимают.
«Новый лот» работает ровно как `/new`, в том числе посреди визарда в любом шаге: хендлер кнопки стоит в админском роутере, который подключён раньше визарда, поэтому текстовые шаги (производитель, модель…) не принимают её за ввод.

**Доступ.** Админский роутер и визард закрыты фильтром `IsAdmin` на уровне роутера. Порядок роутеров: общий (`/start`, `web_app_data` - для всех) → админ → визард → покупатель (только не-админы, только личка).

**Покупатель:**
- `/start` (в том числе с payload): «Здравствуйте! Это бот магазина {SHOP_NAME}. Жмите «Магазин», чтобы посмотреть объявления. Я буду присылать новые объявления - отключить можно кнопкой внизу.» + клавиатура покупателя. Новый покупатель подписывается автоматически; явная отписка при повторном `/start` сохраняется (тогда хвост текста: «Уведомления о новых объявлениях выключены - включить можно кнопкой внизу.»). Админы не подписываются.
- Кнопки уведомлений: «Уведомления выключены. Включить - кнопкой внизу.» / «Уведомления включены.» + обновлённая клавиатура.
- Любой другой текст, фото, стикер: одна строка «Жмите «Магазин» внизу, чтобы посмотреть объявления.» + клавиатура.
- Нажатие чужих (админских) inline-кнопок: алерт «Недоступно».
- Любое сообщение покупателя снимает `blocked_at`: раз пишет - бот не заблокирован.

**Заявка через `web_app_data`** (от любого пользователя): JSON `{"t":"lead","id":"<public_id>","phone":"<необязательно>"}`. Заявка `source=app` от `message.from_user` через тот же `leads.create_app_lead`, что и HTTP-эндпоинт с initData: проверка активного лота, подавление дублей, текст продавцу. Ответ: «Заявка отправлена, продавец свяжется с вами.», для проданного лота «Этот лот уже продан.», для неизвестного/черновика «Лот не найден.». Битый JSON - строка в лог, без ответа.

**Рассылка новых объявлений** (`notify.py`): после успешной публикации (не на идемпотентном повторе) `publisher.publish` запускает фоновую задачу со своей сессией БД. Каждому подписчику (`subscribed`, без `blocked_at`, не админ) - `send_photo`: обложка, подпись «Новое объявление» + пустая строка + подпись поста (всё в пределах 1024), inline-кнопки: «Открыть» (web_app → `{PUBLIC_BASE_URL}/item/{public_id}`) и «Написать продавцу» (если задан `SELLER_USERNAME`). Не больше 20 сообщений в секунду, одна рассылка за раз (lock). `RetryAfter` - ждать и повторить; `TelegramForbiddenError` (заблокировал бота, удалил аккаунт) - `blocked_at`, дальше ему не шлём; прочие ошибки - в лог и пропуск. Итог - `events` типа `notified` с `{sent, failed, blocked}`. Админ после «Опубликовано…» (с админской клавиатурой) получает отдельным сообщением «Лот {public_id}: разослано подписчикам: N».

**Пост в канале** не меняется: кнопки-ссылки t.me, как в «Публикация».

## Продажа (sales.py)
- Триггеры: команда `/sold <public_id>`, кнопка «Продано» в `/list` бота, кнопка в AdminPage Mini App.
- `mark_sold(item_id)`: идемпотентно. `status=sold`, `sold_at`, затем `delete_message` по каждой записи `channel_messages`, включая legacy `cta`. Ошибку удаления логировать в `events` как `delete_failed` и уведомить админа, лот из витрины всё равно уходит.
- Повторный вызов на проданном лоте возвращает успех без действий.

## Заявки (leads.py)
- `POST /api/items/{public_id}/lead`. Лот должен быть `active`, иначе 410.
- В Mini App: заголовок `X-Telegram-Init-Data` валидируется (HMAC, `auth_date` не старше 24 ч). Покупатель - `user` из initData (имя, @username, id). Тело может добавить телефон. Покупатель без username получает ссылку `tg://user?id=...`.
- На сайте: тело `{name, contact}`, contact - телефон или @ник, обязателен. Защита: honeypot-поле, не больше 5 заявок в час с одного IP, не больше 1 заявки с одного контакта на один лот за 10 минут.
- Бот шлёт в `LEADS_CHAT_ID` сообщение: лот (модель, цена, public_id), источник (приложение/сайт), имя и контакт покупателя, кликабельная ссылка на покупателя, если она есть. Фиксируется `notified_at`, в `events` - `lead`.
- Покупателю отвечаем «Заявка отправлена, продавец свяжется с вами».

## API
Публичные:
- `GET /api/items?tags=&price_min=&price_max=&cursor=&limit=20` → `{items: [ItemCard], next_cursor, total}`. Только `active`, сортировка по `published_at desc`, курсорная пагинация. `price_min`/`price_max` - свободный диапазон цены в рублях, границы включительно, оба необязательны, складываются с тегами через AND. `total` - число активных лотов под тем же фильтром (теги + цена), без учёта cursor/limit. ItemCard: public_id, title, device_type, brand, model, storage_gb, variant, color, battery_health, grade, price, cover (URL preview), has_video, published_at, note (полный текст), grade_label, seller_url - этого достаточно плитке без похода за деталями лота.
- `GET /api/items/count?tags=&price_min=&price_max=` → `{total}`. Та же выборка, только COUNT; живой счётчик «Показать N предложений» в шторке фильтров.
- `GET /api/items/price-histogram?tags=` → `{min, max, buckets: [{from, to, count}]}`. Цены активных лотов под остальными фильтрами (теги `price:*` игнорируются, диапазон цены не применяется): `min`/`max` - реальные крайние цены, 12 равных корзин с «круглым» шагом (1/2/2,5/5 × 10ⁿ, не меньше 1 000 ₽) от `min`, округлённого вниз до шага; `[from, to)`, последняя включает `to`. Нет лотов - `{min: null, max: null, buckets: []}`. Гистограмма над слайдером цены.
- `GET /api/items/{public_id}` → полная карточка с массивом media `[{kind, preview, full|video, duration}]`. Для `sold` - 410.
- `GET /api/menu` → `{categories: [{code, label, device_type, count, grades: {A,B,C}, models: [{slug, label, count, price_min, price_max, storages: [int], variants: [str], grades: {A,B,C}, device_type, color, cover}]}]}`. Данные палитры каталога, только `active`. Раздел - `items.category` в фиксированном порядке iphone / ipad / macbook / watch / airpods / other (неизвестный код = other), пустые разделы не отдаются; подписи: iPhone, iPad, Mac, Watch, AirPods, «Другие устройства». Модель: `slug` = слаг тега `model:*` (`tags.model_tag_def`, тот же, что ставят фильтры), `label` для не-Apple с производителем («Samsung Galaxy S24»); порядок моделей - у Apple как в каталоге (новые первыми), в other - по числу лотов. `device_type`, `color`, `cover` - от самого свежего лота модели (обложка = первое фото, видео пропускается; нет фото - null, фронт рисует силуэт). Два запроса: активные лоты, затем фото свежих лотов.
- `GET /api/tags` → теги по kind с количеством активных лотов. Без параметров - простые счётчики, теги с нулём не отдаются. С `tags` и/или `price_min`/`price_max` - фасеты под текущий выбор: отдаются все теги, у которых есть хоть один активный лот, а `count` - число лотов, подходящих под выбор во всех остальных kind (свой kind не учитывается; диапазон цены считается kind `price_band`). Ноль остаётся в ответе, фронт его приглушает. Порядок внутри kind не зависит от выбора.
- `POST /api/items/{public_id}/lead` - см. «Заявки».

Админские (`X-Telegram-Init-Data`, HMAC, `auth_date` ≤ 24 ч, `user.id` в `ADMIN_IDS`, иначе 403):
- `GET /api/admin/items?status=active`
- `POST /api/admin/items/{public_id}/sold`
- `PATCH /api/admin/items/{public_id}` → правка любого поля активного лота: category, device_type, brand, model, year, storage_gb, variant, color, battery_health, grade, kit, price, note. Валидация как в визарде (`services/lot_edit.py`): для Apple модель и опции из каталога, одиночные опции заполняются сами; смена категории/модели сбрасывает зависимые поля, если они не пришли в том же запросе. 422 `{detail: {field, message}}` по-русски, проданный/черновик → 409. После сохранения: теги пересчитываются, подпись в канале перерисовывается `edit_message_caption` с `post_keyboard` (кнопки передаются заново, иначе Telegram их снимет); `channel_updated=false`, если Telegram не принял.
- `POST /api/admin/items/{public_id}/cover` `{file_unique_id}` → фото лота становится обложкой (позиция 0), пост в канале меняет фото на месте через `edit_message_media` с той же подписью и кнопками. Видео/чужое фото → 422.
- `GET /api/admin/catalog` → данные для формы правки: категории, модели с памятью/вариантами/цветами, типы устройств, комплект, состояния, варианты памяти для «Другое».
- `GET /api/admin/items` отдаёт также все поля лота и `photos` (первое - обложка).
- В боте до публикации: предпросмотр → «Изменить поле» → «Обложка» (от двух фото).

## Деплой
- Lab: `deploy/lab-deploy.sh` → `$LAB_URL` (подпуть на общем staging-сервере). Перед каждым деплоем - снапшот БД lab (см. ПРАВИЛА в `LOOP.md`).

## Вне MVP (не делать)
Бронь, оплата, чат с покупателем внутри приложения, текстовый поиск, сортировка кроме «сначала новые», история цен, несколько магазинов, синхронизация с Avito, аналитика, удаление медиа проданных лотов, отдельный дизайн сайта, SEO, мультиязычность, видео больше 20 МБ.
